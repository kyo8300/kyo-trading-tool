# Security

## コミット前チェック

- [ ] ハードコードされた秘密情報がない（API キー、パスワード、トークン、取引所の認証情報）
- [ ] すべてのユーザー入力が検証されている
- [ ] SQL はパラメータ化クエリ（文字列連結禁止）
- [ ] HTML 出力はサニタイズ済み（XSS）
- [ ] 認証・認可が必要な箇所で確認されている
- [ ] 外部に公開するエンドポイントにレート制限がある
- [ ] エラーメッセージが内部情報（スタック、パス、秘密）を漏らしていない

## 秘密情報の管理

- ソースコードにハードコードしない。環境変数か secret manager を使う
- `.env*` と `secrets/` は読み取り自体を `.claude/settings.json` の deny で禁止している
- 起動時に必須の秘密情報が揃っているか検証する
- 漏れた可能性がある秘密はローテーションする

## トレーディングツール特有の注意

- 取引所 API キーは**読み取り専用**と**取引用**を分け、必要最小限の権限にする
- 実注文を出すコードパスは、テスト・開発環境では必ず paper/sandbox モードになるよう設計する
- 金額は浮動小数点で扱わない（Decimal / BigInt / 整数の最小単位）
- レート制限・リトライ・タイムアウトを外部 API 呼び出しに必ず付ける

## 問題を見つけたとき

1. 作業を止める
2. CRITICAL を先に直してから続行する
3. 漏れた秘密はローテーションする
4. 同種の問題がないかコードベース全体を確認する
