# Intent: trade-decision-journal（インフルエンサー予想の追跡と、自分の売買判断の記録・答え合わせ）

- 作成日: 2026-09-13
- 状態: approved
- 旧仮称: `ai-stock-picker`（討論の結果、核が「AI が銘柄を選ぶ」から「予想と自分の判断を記録して検証する」に移ったため改名）

## 問題

kyo（投資経験約半年、楽天証券、米株）は株式売買に力を入れたいが、銘柄を選ぶ根拠を自分の中に持っていない。
X 上の Serenity（@aleabitoreddit、AI インフラ部品の小型〜中型米株、フォロワー約100万人）のような発信者の予想を参考にしたいが、
「誰の予想が、どの条件で、どのくらい当たっているか」を数字で見たことがなく、当たった投稿だけが目立つ生存者バイアスの中で判断している。

さらに、発信者の投稿を見てから買うと既にフォロワーが殺到して高値になっている（クラウディング）ため、
「予想を見て買う」を素朴にやるだけでは利益が出ない可能性が高い。Serenity 本人も「盲目的に信じるな、自分で検証しろ」「決算で検証されるのを待て」と言っており、
本人の実績（YTD +501% 等）は独立検証がなく、直近は本人が大きなドローダウンを認めている。

一方、Serenity のツイートアーカイブや方法論をエージェント用スキルとしてまとめた既存ツール（yan-labs/serenity-aleabitoreddit、trackserenity.com、finsig.ca 等）は既にあり、
「発信者の知識ベースを自作する」こと自体には差別化の価値がない。kyo にしか作れないのは「自分の資金・自分のルールで、何を見て、なぜ買い、結果どうだったか」の記録である。

## 望む結果

- 追跡対象の発信者（必須: Serenity。任意の2人目として FabyΔ @FABYMETAL4 を、複数情報源を扱える構造の検証サンプルに使う）の銘柄言及が、投稿日・銘柄・投稿時点の株価・発信者の想定保有期間とともに記録されている
- 時間軸は **(A) 発信者のテーゼに乗って数ヶ月〜1年保有** を主軸とし、四半期決算・供給契約や増産ニュース・株価 ±X% などの中間チェックポイントで 3 ヶ月ごとに「予想が当たりつつあるか」を部分判定できる
- 発信者ごとに「言及から N 日後 / 四半期決算後 / 想定保有期間経過後の株価変化」が一覧で見られ、的中率・平均リターンが数字で分かる
- kyo 自身の売買判断（買う／見送る、理由、参照した情報源、金額）が同じ形式で記録され、発信者の予想と並べて比較できる。最終目的は**実口座で利益を上げること**であり、記録はそのための手段
- 3 ヶ月運用した時点で、kyo が「この発信者の、この種の予想は信頼できる／できない」を自分の言葉で説明できる状態になっている
- paper trading は「記録の仕組みが動くこと」を確かめる**短い関門（数週間を想定）**であり、条件を満たしたら少額の実弾に移る。paper に留まり続けることはゴールではない
- paper の成績と並べて、スリッページ・手数料・為替コストを差し引いた**実弾での期待値の概算**が表示される。paper のうちから「実弾ならどれくらい取れそうか」が見える
- 発注は最初は全件 kyo が確認してから行う。自動化の判断基準は、上記の記録から得たデータをもとに後で決める

## 影響範囲

### 触れるもの
- X 上の発信者の投稿（Serenity 必須、FabyΔ 任意。将来追加可能な構造にする）
- 米国株の株価データ（言及時点と事後の比較用）
- kyo 自身の売買判断と結果のログ（新規に作るデータ）
- paper trading（仮想売買）の口座・残高データ

### 触れないもの
- 実口座（楽天証券）への**自動**発注。初期は paper、次に手動での少額実弾（ツールは記録と判断支援）。自動発注は将来の検討事項
- 日本株（当面対象外。追跡対象は米株のみ）
- 投稿直後の急騰を数日で抜く短期戦略 (B)。時間軸 A に集中する
- Serenity の知識ベース・方法論スキルの自作（既存の yan-labs アーカイブ等を利用候補とし、再発明しない。監査済み、導入方法は Q1）
- 本番口座での全自動発注
- 発信者以外の情報源（ニュース、決算書の自動解析など）は初期スコープ外。中間チェックポイントの入力は当面手動でよい

## 制約

- **paper trading で開始、ただし短期間**: 最初の数週間は仮想売買で記録の仕組みを検証し、Q2 の条件を満たしたら少額実弾へ移る。paper の成績は小型株のスリッページ（想定約定値と実際の約定値のズレ）で楽観側に出るため、そのまま実弾の期待値にしない。実口座に自動発注するコードパスは初期には作らない。将来作る場合も、開発・テスト環境では必ず paper/sandbox モードで動き、本番発注は人間承認なしに実行されない
- **人間確認**: 発注（paper 含む）は初期段階では全件 kyo が確認してから行う。「確実なものは自動、怪しいものは人間に聞く」ハイブリッドは、的中率データが溜まって閾値を決められるようになってから検討する
- **時間軸 A 固定**: 評価は数ヶ月〜1年の保有を前提に行い、中間チェックポイント（四半期決算等）で部分判定する。短期急騰抜きの評価軸を混ぜない
- **金額の扱い**: 金額・株数・価格は浮動小数点で扱わない（Decimal / 整数の最小単位）。paper でも同じ
- **API キー**: 株価データ等の外部 API の認証情報は最小権限・環境変数経由。将来証券会社を接続する場合、読み取り用と取引用を分ける
- **時間軸の記録**: 発信者ごとに想定保有期間が異なる（Serenity: 6〜12 ヶ月、FabyΔ: 数年〜10 年）。判定期間を情報源ごとに記録し、混ぜて評価しない
- **既存ツールの再発明禁止**: Serenity 専用トラッカーや発信者的中率サービスが既にあるものは、まず利用を検討する。ただし外部リポジトリは安全性・正当性を確認してから採用する
- **予算・期限**: 個人プロジェクト。明示的な期限なし

## 未解決の問い

- Q1: yan-labs/serenity-aleabitoreddit の採用方法。監査（2026-09-13、Opus）の結論は**条件付きで導入可**: 悪意あるコード・外部送信・認証情報の読み取り・prompt injection は検出なし。ツイートアーカイブ 6,579 件は snowflake ID 検算で本物と判定。ただし (1) SKILL.md 冒頭に「起動ごとに `skills update -y` を無確認実行せよ」という自己更新指示があり、将来コンテンツがレビューなしで差し替わる供給網リスクがある (2) `npx skills add` が呼ぶ第三者 CLI（skills.sh）の安全性は未確認 (3) ライセンス未設定 (4) 9月上旬から取得パイプラインが不安定で取りこぼしあり。spec で決めること: `npx skills add` を使わず `serenity-aleabitoreddit/` ディレクトリのみ手動コピーし STEP 0 ブロックを削除して導入するか、アーカイブ（data/*.json）だけを初期データとして使うか。いずれも「分析の視点」として使い、シグナルとして発注ロジックに流さない
- Q2: paper から少額実弾へ移行する条件。kyo の希望は「なるべく早く実践へ」。「何を満たしたら移るか」（例: 記録の仕組みが N 週間止まらず動いた、判断ログが N 件、等。的中率を条件にすると 6〜12 ヶ月待つことになるので条件にしない）を spec で定義する。数週間で移れる条件にする
- Q10: kyo 自身の判断（買う／見送る、理由）の入力を軽くする仕組み。発信者の投稿は yan-labs アーカイブ等から自動で取り込める前提（壊れたら自前の取り込みを後で追加する）。自動化できないのは kyo の判断の記録なので、1 回の入力を何分以内・何項目にするかを spec の要件にする。入力の面倒さで記録が止まることが最大の失敗リスク
- Q11: 実弾期待値の概算方法。スリッページ（銘柄の出来高・スプレッドから推定）、楽天証券の手数料、為替コストをどう見積もるか
- Q3: 中間チェックポイントの具体的な定義（何日後、±何%、決算の何を見るか）
- Q4: X の投稿取得手段。X API は有料・制限あり。既存アーカイブ（Q1）、手動入力、スクレイピングの可否と合法性を spec で検討
- Q5: 将来実弾に移る場合、楽天証券は米株の自動売買 API を一般公開していない可能性が高い。手動発注 + 記録で続けるか、対応証券会社を別途検討するか
- Q6: 「確実」を機械が判定する基準。データが溜まった後に決める。初期スコープでは決めない
- Q7: 発信者の追加基準。誰を、どの根拠で追跡対象に入れるか
- Q8: 株価データの取得元（無料・遅延あり／有料・リアルタイム）
- Q9: paper trading の実装方針（自前で残高・約定を記録するか、既存の paper trading サービスを使うか）

## 討論の要点

- **「発信者の予想を知識データとして溜めて、それをもとに買う」（初案）** → 不採用（そのままでは）。理由: 的中率が未検証、後追いは高値掴み、既に yan-labs 等が同じものを作っている。「買う前に記録して答え合わせする」に軸を移した
- **「AI に銘柄を選ばせる vs 自分でファンダメンタルを学ぶ」** → 二者択一にしない。自分の判断と発信者の判断を同じテーブルに記録して採点することで、学ぶべき箇所が見えるようにする
- **「1ヶ月待つのは微妙」** → Serenity の手法自体が 6〜12 ヶ月先を狙うため、短期で答え合わせはできない。ただし四半期決算などの中間チェックポイントで部分判定はできる、で折り合い。時間軸は A で確定
- **短期急騰抜き (B)** → 不採用。100万人のフォロワーと後追い競争になり不利。A に集中する
- **「確実なものは自動発注、怪しいものは人間に聞く」ハイブリッド** → 方向は採用するが、初期は全件人間確認。閾値はデータが溜まってから
- **「数千円で試す」** → 手数料・為替スプレッド・小型株のスプレッドで溶けやすく、学びの量は paper と大差ないことを共有。**paper で開始**に決定。ただし kyo は「ずっと paper はいやだ、利益爆上げの目的は変わらない」と明言。paper は数週間の関門とし、実弾移行条件は Q2 で早めに設定する
- **FabyΔ の追加** → kyo は「どっちでもいい」。必須ではなく、時間軸の異なる情報源を扱える構造を検証するための任意サンプルに位置づけた
- **調査で判明した訂正**: Serenity のフォロワー数は当初「約47万」と提示したが 2026年5月時点の古い数字だった。kyo 指摘の「約100万人」を正とする
