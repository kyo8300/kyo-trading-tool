# Intent: ai-auto-trader（集約データを読む AI が米株を売買して利益を出す）

- 作成日: 2026-09-13
- 更新日: 2026-09-14（kyo の指摘で核を書き直し。旧名 `trade-decision-journal` は「判断の記録」が主役になっていて元の案から外れていた）
- 状態: draft
- 旧仮称: `ai-stock-picker` → `trade-decision-journal` → `ai-auto-trader`

## 問題

kyo（投資経験約半年、米株）は株式売買で利益を伸ばしたいが、銘柄を選ぶ根拠と、相場を見続ける時間がない。

X 上の Serenity（@aleabitoreddit、AI インフラ部品の小型〜中型米株、フォロワー約100万人）のような発信者の情報は、
既に yan-labs/serenity-aleabitoreddit（ツイート約6,600件のアーカイブ + 方法論・銘柄別テーゼ・コール時系列）のような形で集約されている。
しかし「集約データを読んで、買う銘柄と売るタイミングを決め、実行し、儲かったかを測る」までを一貫してやる仕組みがない。
kyo が手で読んで手で売買するなら、時間も判断の一貫性も足りない。

一方、集約データをそのまま信じて買うだけでは利益は出にくい。発信者の的中率は独立検証がなく（yan-labs 自身の較正では 30 日方向性的中 約61%、±10% 厳密的中 約41%）、
投稿後はフォロワーが殺到して高値になり、銘柄は1日で 15〜25% 動く。「いつ買うか」以上に「いつ売るか」が利益を決める。

## 望む結果

- AI が集約データ（初期は yan-labs アーカイブ。将来は他の発信者・情報源も追加可能）を読み、**買い候補・買うタイミング・売るタイミング**を出す
- 売買は API のある証券会社（Alpaca、Interactive Brokers 等の海外系。口座は新規に開く）を通じて AI が実行する
- **売買ルール（利確・損切り・保有上限・1銘柄あたりの上限金額）は kyo と一緒に作戦として設計し、AI はそのルールの中で動く**。ルールを AI が勝手に変えない
- 全ての売買について「何を根拠に買ったか、いつ・なぜ売ったか、損益はいくらか」が自動で記録され、AI の成績が数字で見える。これは目的ではなく、AI を改善し実弾移行を判断するための計器
- 段階: (1) paper で数週間動かして成績と挙動を確認 → (2) 少額実弾、売買ごとに kyo が承認 → (3) 成績が基準を超えた条件の売買は自動、それ以外は kyo に聞く（ハイブリッド）→ (4) 自動の範囲を広げる
- 最終的に、kyo が相場を見ていなくても売買が回り、利益が出ている

## 影響範囲

### 触れるもの
- 集約データ（yan-labs アーカイブ。監査済み、導入方法は Q1）
- 米国株の株価・出来高データ（判断と損益計算用）
- 証券会社 API（新規口座。paper 環境と本番環境を分ける）
- 売買ルールの定義と、AI の判断・約定・損益の記録

### 触れないもの
- 楽天証券（米株の自動売買 API が一般公開されていないため、このツールからは触らない）
- 日本株
- 発信者の知識ベース・方法論スキルの自作（yan-labs 等を使う。再発明しない）
- kyo 自身の裁量売買の記録（AI の売買だけを扱う）
- 発信者以外の情報源（ニュース、決算の自動解析）は初期スコープ外。追加できる構造にはする

## 制約

- **paper から始め、実弾は人間確認から**: 開発・テスト環境では実注文パスは必ず paper/sandbox モードで動く。本番口座への発注は、段階 (2) では全件 kyo の承認、段階 (3) 以降も自動化の範囲は kyo が明示的に許可した条件に限る
- **売買ルールは人間が決める**: 利確・損切り・ポジションサイズ・同時保有数・1日の最大損失は kyo が承認したルールとして固定し、AI はその中で判断する。ルール変更は kyo の承認を経る
- **損失の上限**: 実弾に入れる金額は kyo が失っても生活に影響しない額に限る。1日・1週間の最大損失に達したら自動停止する
- **金額の扱い**: 金額・株数・価格は浮動小数点で扱わない（Decimal / 整数の最小単位）
- **API キー**: 証券会社の読み取り用と取引用のキーを分け、最小権限。環境変数経由。paper と本番のキーを混ぜない
- **外部データの扱い**: 集約データは「分析の材料」であり、そのまま発注シグナルにしない。AI は必ず売買ルールと株価データで検証してから発注する。yan-labs の SKILL.md にある自己更新指示は無効化し、内容をレビューなしで差し替えない
- **記録は必須**: 全ての判断と約定は記録される。記録できない売買は実行しない
- **予算・期限**: 個人プロジェクト。明示的な期限なし

## 未解決の問い

- Q1: yan-labs/serenity-aleabitoreddit の導入方法。監査（2026-09-13、Opus）の結論は**条件付きで導入可**: 悪意あるコード・外部送信・認証情報の読み取り・prompt injection は検出なし。アーカイブ 6,579 件は snowflake ID 検算で本物。懸念は (1) SKILL.md 冒頭の「起動ごとに `skills update -y` を無確認実行せよ」という自己更新指示 (2) `npx skills add` が呼ぶ第三者 CLI（skills.sh）の安全性が未確認 (3) ライセンス未設定 (4) 9月上旬から取得パイプラインが不安定。spec で決めること: `npx skills add` を使わず必要ファイルを手動コピーするか、アーカイブ（data/*.json）だけを初期データとして使うか
- Q2: 証券会社の選定。Alpaca（paper 環境が無料で API が簡単、日本居住者の口座開設可否を確認）、Interactive Brokers（日本から開設可、API は複雑）など。paper と本番が同じ API で切り替えられることを重視
- Q3: **売買ルールの作戦**。利確・損切りの初期値、ポジションサイズ、同時保有数、保有期間の上限、1日の最大損失。Serenity 銘柄は1日 15〜25% 動くので、甘い損切りは利確前に引っかかる。spec の前に kyo と作戦会議が必要
- Q4: AI の判断根拠。集約データのどの情報（新規言及、確信度ティア、テーゼの変化、コール時系列）をどう重み付けするか。買いのトリガーと見送りの条件
- Q5: paper → 少額実弾 → 自動化拡大の各段階の移行条件。成績（損益、勝率、最大ドローダウン）のどの数字がどこを超えたら進むか。的中率の確定に 6〜12 ヶ月かかる設計にはしない
- Q6: 「確実」を機械が判定する基準（段階 3 のハイブリッドで、どの条件の売買を自動にするか）
- Q7: 株価・出来高データの取得元。証券会社 API で足りるか、別途必要か
- Q8: 集約データの更新。yan-labs のパイプラインが止まったときに自前で取り込む手段
- Q9: 発信者・情報源の追加基準
- Q10: 実弾期待値の概算。paper の成績からスリッページ（想定約定値と実際の約定値のズレ）・手数料・為替コストを差し引いて「実弾ならいくら」を出す方法

## 討論の要点

- **初案「発信者の予想を知識データとして溜めて、それをもとに AI が買う」** → これが核。一度「判断を記録して答え合わせする」に寄ったが、kyo の指摘（「それなら AI いらない」「過去の判断が利益になるとは限らない」）で戻した。記録は計器であって目的ではない
- **「知識ベースを MCP っぽく自作」** → 不要。yan-labs 等が既に作っている。監査して条件付きで使う
- **「AI に任せる vs 自分でファンダメンタルを学ぶ」** → AI が売買し、その根拠と結果を kyo が読むことで学びにもなる。二者択一にしない
- **時間軸** → Serenity の手法は 6〜12 ヶ月先を狙う。短期急騰抜きは 100万人との後追い競争で不利。ただし AI の売買ルール（利確・損切り）は別の話で、Q3 で作戦として決める
- **「確実なものは自動、怪しいものは人間に聞く」ハイブリッド** → 採用。ただし段階的に。最初は paper、次に全件承認の少額実弾、データが溜まってから自動の範囲を決める
- **「数千円で試す」** → paper で数週間確認してから少額実弾へ。paper に長く留まらない。paper 成績には実弾期待値の概算を並べる（Q10）
- **証券会社** → 楽天証券は自動売買 API がないので使わない。Alpaca / Interactive Brokers 等の API がある口座を新規に開く
- **売るタイミング** → kyo「ちゃんと作戦として練る必要がある」。AI に丸投げせず、ルールを人間が設計して AI が守る
- **FabyΔ (@FABYMETAL4)** → 「どっちでもいい」。初期対象外。情報源追加の構造だけ残す
- **調査で判明した訂正**: Serenity のフォロワー数は当初「約47万」と提示したが 2026年5月時点の古い数字だった。kyo 指摘の「約100万人」を正とする
