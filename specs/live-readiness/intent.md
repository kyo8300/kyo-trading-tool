# Intent: live-readiness（paper → 少額実弾の移行条件を、テーゼの時間軸に合わせて作り直す）

- 作成日: 2026-10-06
- 更新日: 2026-10-06（kyo の回答で Q1〜Q4 を決定に変更）
- 状態: draft
- 親: `specs/ai-auto-trader/`（spec Q5 の移行条件、R-22 / R-23 の report を変更対象とする）

## 問題

paper 運用は 2026-09-18 頃から cron で回り、今日で約 19 日（営業日 13 日）。`trader report` は期間損益 0、閉じた trade 0 件、最大 DD 0.06%、実弾期待値 -55.24（ほぼ為替コスト見込み -50 そのもの）。保有 5 銘柄（BE / DRAM / GOOGL / HOOD / IREN）は高値ベースで +3.5%〜+17.9% だが、どれも部分利確 +30% に届いていない。

親 spec の Q5 で決めた移行条件は「paper 3 週間以上 + **閉じた trade 10 件以上** + 実弾期待値プラス + 最大 DD < weekly 上限 + キルスイッチ誤作動なし」。しかし売買ルール（損切り -15% / 部分利確 +30% / トレーリング 20% は部分利確後のみ / 保有上限 120 日）は Serenity のテーゼ（6〜12 ヶ月）前提で設計されていて、数週間では trade がまず閉じない。5 枠が埋まると LLM も呼ばず新規買いもない。つまり**ルールは長期前提、移行条件は短期前提で、噛み合っていない**。このままだと「閉じた trade 10 件」は数ヶ月〜1 年近く満たせず、親 intent の「paper に長く留まらない」という方針と矛盾する。

困っているのは kyo。少額なら早めに live に進みたいのに、今の条件では進めるか判断できない。また、条件が「閉じた trade」に依存するため、report の数字（期間損益 0、勝率なし）が paper の実態（含み益 +3〜18%）を表していない。

## 望む結果

- 移行条件が「閉じた trade の件数」ではなく、**口座全体の損益（実現 + 含み益、時価）を同期間の SPY（市場平均）と比べる**形になっている。テーゼの時間軸（6〜12 ヶ月）で「市場より良いか」を見る条件なので、trade が閉じなくても判定できる
- 移行条件（2026-10-06 kyo 決定）:
  1. paper を **6 週間以上**回している
  2. 口座全体の損益率（含み益込み）が、同期間の SPY のリターンを**上回っている**
  3. **最も儲かった 1 銘柄を除いても** SPY 以上（1 銘柄の急騰だけで合格にならない）
  4. 親 spec から引き継ぐ: 実弾期待値がプラス / 最大 DD が weekly 上限未満 / キルスイッチが誤作動していない
  5. `trader close <ticker>` で paper の保有を 1 銘柄売り、売り注文の経路（判断 → 承認 → 注文 → 約定 → trade 記録）が本番 cycle と同じ経路で**1 回以上通っている**
- `trader report`（または `status`）に、同じ期間の SPY のリターンと、paper ポートフォリオの損益率（実現 + 評価）が**並んで表示**され、上の各条件について「満たした / 未達」が一目で分かる
- 判定は % で行い、paper の capital（$2,500）と live の額（小さく始める）が違っても同じ条件で読める
- 最終判断は kyo。report は判定結果を表示するだけで、自動で「合格」と宣言したり live に切り替えたりしない
- 条件が親 spec（Q5）の記述と食い違わない。親 spec の Q5 は本 intent を指す形に更新されている

## 影響範囲

### 触れるもの
- paper → 少額実弾の移行条件の定義（親 spec Q5 の置き換え）
- `trader report` / `trader status` の表示（SPY 比較、評価損益ベースの成績、移行条件の判定結果）
- SPY の価格データの取得（既存のマーケットデータ経路に 1 銘柄増える想定。取得元は spec で決める）
- **`trader close <ticker>` コマンドの追加**: kyo が手で指定した保有銘柄を売る。売り decision（origin は手動であることが分かる値）→ 承認 → 注文 → 約定 → trade 記録まで、ルール発火の売りと同じ経路を通す。paper で売り経路を検証するためのもの
- 親 spec `specs/ai-auto-trader/spec.md` の Q5 の記述（本 intent への参照に更新）

### 触れないもの
- **売買ルール `rules/trading-rules.yaml` の比率と `capital_usd`**（損切り・利確・トレーリング・保有上限）。ルールは変えず、条件のほうを合わせる。paper の `capital_usd: 2500` もそのまま。ルール変更が必要だと分かったら別 intent
- **live 口座の開設・入金・ブローカー選定・`MoomooBroker` / `WebullBroker` の実装・初回 live 発注**。次の intent で扱う。本 intent は「進んでよいと判定できる状態」を作るまで
- AI の判断ロジック（analyst / prompt）、entry / exit のルール判定コード（`close` は exit ルールを変えず、売りの経路だけを共有する）
- 段階 (3)(4)（条件付き自動化）の条件

## 制約

- **後出しで甘くしない**: 条件は「paper の成績を見た上で」変えるので、現在の保有が有利に見える数字に寄せた条件にならないようにする。閾値の根拠を書き、現状の数字をそのまま「合格」にするための条件にしない。「最大 1 銘柄除外」はそのための偏り対策
- **SPY との比較は同じ期間・同じ起点**で行う。ポートフォリオ側は実現損益 + 評価損益（時価）で、コスト控除後（R-23 の実弾期待値）の数字も並べる。6 週間の起点・コスト控除後を合格判定に使うかは spec で決める
- **売りの処理の確認を落とさない**: 「閉じた trade 10 件」を外す代わりに、`trader close` で売り経路を paper で 1 回以上通してから live に進む。`close` はルール（yaml）を変えずに実現する
- **`close` は手動の売りであり、記録される**: 親 intent「記録できない売買は実行しない」を引き継ぐ。手動であることが decision に残り、report で「ルール発火の売り」と区別できる。live モードでは通常の売りと同じく kyo の承認レコードが必要（R-17 を迂回しない）
- **資金額のずれは承知で進む**: paper は $2,500、live は小さく始める（目安 $500。親 intent の「失っても生活に影響しない額」）。1 銘柄上限が $375 → $75 に変わるので live では整数株で買えない銘柄（GOOGL / BE 等）が出て銘柄構成が変わりうるが、判定は % で見ることで比較する。このずれは認識した上での判断
- **金額は Decimal、SPY データも境界で検証**（親 spec N-1 / N-5 を引き継ぐ）
- 親 spec の他の条件（実弾期待値プラス、最大 DD < weekly 上限、キルスイッチ誤作動なし）は維持する
- 技術選定・設計は spec で決める。本 intent は条件の「意図」だけ

## 討論の要点

- **「閉じた trade 10 件」を外す**: 採用（本 intent の核）。理由: ルールが 6〜12 ヶ月前提なので数週間で閉じない。件数条件はルールと時間軸が合っていない
- **代替案「ルールのほうを短期に変える（利確 +15% など）」**: 不採用。親 intent で「短期急騰抜きは 100 万人との後追い競争で不利」「テーゼは 6〜12 ヶ月」と決めており、live に早く進みたいという理由でルールを曲げるのは本末転倒。ルールは変えず条件を合わせる
- **代替案「条件を変えずに、少額なら例外として今 live に進む」**: 不採用。「数字で判断する」という親 intent の方針（記録は計器）に反する。条件を書き直すほうが後から辿れる
- **反論「評価損益 vs SPY は 3 週間ではノイズ」**: 正しい。AI インフラ小型株は β が高く、相場が上がれば SPY を超えるのは腕ではなく市場。kyo は「6 週間以上 + 最大 1 銘柄除外」を選んだ。6〜12 ヶ月のテーゼを完全に検証するには足りないが、親 intent は「的中率の確定に 6〜12 ヶ月かかる設計にはしない」としているので、これは意図的な妥協。live の額を小さくすることで妥協分のリスクを抑える
- **反論「件数条件を外すと売りパスが未検証のまま live に行く」**: 正しい。件数条件は暗黙にこの役割を持っていた。kyo は手動 `close` コマンドで経路を 1 回通す案を選んだ。これは「ルールを変えずに売りを起こす」唯一の方法で、live でも kyo が裁量で手仕舞いしたいときに使える副産物がある
- **「SPY 以外の比較対象（半導体 ETF、Serenity 言及銘柄の等金額バスケット）」**: 候補として記録。SPY は「市場平均に勝っているか」という最も素直な問いなので初期は SPY。バスケット比較は「Serenity をなぞるだけと比べて AI の選別に価値があるか」を測るもので別の問い。spec で追加の比較対象を 1 つ足すのは可
- **ブローカー選定・live 接続**: 次の intent にする（Q3 決定）。Alpaca live は海外送金・確定申告、国内 2 社は Broker 未実装で、いずれも「条件を決める」とは別の作業量
- **capital のずれ**: 討論の中で気付いた点。yaml は「paper でも live 予定額と同じ額に」と書いているが現状 $2,500 で稼働している。kyo は「ずれ承知で進む、判定は %」を選んだ（Q4 決定）。live で買える銘柄が変わる点は制約に明記した
